# Audit et remise à plat du 8 octobre 2026

## Base examinée avant modification

Le dépôt était propre sur `main`, au commit `385a4a8`. L'inventaire portait sur
979 fichiers suivis, 42 scripts chargés par l'entrée HTML et 94 ressources de
précache, complétées par les catalogues d'images. L'analyse a relevé les
enregistrements globaux, consommateurs, chemins statiques et dynamiques, clés de
stockage, migrations, outils d'import, tests et procédures.

Avant les changements, les six suites Node existantes ont été exécutées. Seize
écrans mobile/PC ont été enregistrés avec leurs textes, DOM, dimensions et styles.
Les empreintes des contenus, images, CSS, polices, bibliothèques et migrations
ont été conservées ; les algorithmes ont été comparés par AST indépendamment du
formatage. Ces références sont décrites dans la [maintenance](maintenance.md).

## Décisions et dépendances

| Élément | Décision | Justification |
| --- | --- | --- |
| Site statique, scripts classiques et espaces `JDD*` | Conserver | Architecture fonctionnelle, déploiement et PWA déjà cohérents |
| Dossiers publics `scripts`, `styles`, `data`, `image`, `fonts`, `vendor` | Conserver leurs chemins | Anciens clients, cache, données et liens publics |
| Rendu Culture G. dans le contrôleur global | Isoler dans `scripts/app/culture-questions.js` | Responsabilité distincte ; mêmes fonctions, callbacks et ordre d'exécution |
| Six échappements HTML équivalents | Une définition dans `scripts/core/dom.js` | Même conversion `String` et mêmes cinq entités, testées avec les cas limites |
| Conservation du défilement dans le registre | Déplacer dans le helper DOM | Même API, même logique, sans changement de comportement |
| Sélection des deux joueurs aux échecs/Duel Foot | Une fonction dans l'éditeur partagé | Anciennes implémentations strictement identiques ; 100 combinaisons comparées |
| SVG Accueil/Pause identiques | Constantes partagées dans `JDDVisuals.icons` | Littéraux strictement identiques ; variante accessible de Devine Tête conservée |
| Moteurs, seuils, timers et migrations | Conserver | Leur diversité reflète des règles différentes ; aucune simplification du gameplay |
| Distributions Supabase Node/navigateur | Conserver les deux à 2.117.2 | Cibles distinctes, aucune mise à niveau |
| CSS Leaflet référençant des images absentes | Ajouter les cinq PNG officiels de Leaflet 1.9.4 | Compléter la distribution existante, sans changer ses JS/CSS ou les épingles personnalisées du jeu |
| Fonctionnalités regroupées dans leur contrôleur | Conserver ce découpage | Éviter la fragmentation des états, horloges et sauvegardes |

Le rendu de Culture G. ne possède pas le tirage, la navigation ou l'organisateur
de la partie. Ces responsabilités restent dans `main-game.js`. Le choix des
joueurs et la transaction DOM ont leur composant partagé existant ; aucun
framework ni outil de compilation n'est introduit.

## Classement, archives et suppressions

- Les dix documents techniques de racine sont déplacés dans `docs/games/`,
  `docs/data/`, `docs/design/`, `docs/backend/` et `docs/operations/`. Le README
  principal, l'architecture et la maintenance les relient ; les consignes du
  propriétaire restent à la racine dans `AGENTS.md`.
- Les cinq importeurs et leurs trois fichiers de décisions sont regroupés dans
  `tools/imports/` et `config/`. Les deux préparateurs cartographiques sont dans
  `tools/geography/` ; le client et le contrôle Supabase Node sont réunis dans
  `tools/cloud/`. Les modèles d'emails rejoignent `supabase/templates/`.
- Les 22 suites existantes sont classées en `tests/unit/` et `tests/browser/`,
  avec tous leurs scénarios. Les copies de serveur HTTP sont mutualisées et les
  fixtures Supabase sont importées directement ; l'exécution d'un morceau de code
  extrait du texte d'un autre test disparaît.
- `scripts/app/killer.js` et `data/killer.gestures.js` sont archivés octet pour
  octet. Aucun script chargé, cache, DOM courant ou jeu actif ne dépendait d'eux.
- `patches/apero-fixes.js` ne contenait que deux commentaires de délimitation,
  sans code ni consommateur. `image/NEW IMAGE` était un placeholder d'un octet,
  sans format d'image ni référence. Ce sont les deux seuls fichiers supprimés
  sans conservation en archive. Les dossiers devenus vides `patches/` et `lib/`
  disparaissent après le déplacement de leurs contenus utiles.
- Les mentions d'un cache v20 et de brouillons réseau lors d'un ancien import
  deviennent des [notes historiques](archive/import-environment-notes.md), sans
  contredire la procédure actuelle. Les commandes déplacées et une consigne Auth
  dépassée sont corrigées dans la documentation, sans toucher aux textes du jeu.

## Éléments conservés par prudence

Les PNG sources des illustrations, masters d'icônes, anciens visuels et URLs
publiques restent dans `image/`. Ils ne sont pas des doublons à supprimer sur la
seule base de leur nom : certains servent de sources de production, de références
de test ou de compatibilité avec des versions installées. Les assets actuels
gardent exactement leurs octets, transparence, résolution et noms publics.

Les fichiers `papua.png` et `west_papua.png` ont les mêmes octets mais deux
consommateurs de données distincts. Fusionner leurs URLs modifierait les banques
et imports ; les deux sont donc conservés. Les doublons textuels des classeurs,
identifiants et trois lignes Quiz360 en attente ne sont pas dédupliqués ou édités.

Les quatre migrations SQL et deux modèles d'emails restent intacts. Aucune
migration, inscription, modification de compte ou écriture de résultat n'est
exécutée contre Supabase réel pendant ce nettoyage. La proposition réseau dans
`supabase/environment-network.json` est un document de configuration ; elle ne
prouve pas l'état actif d'un environnement.

## Cohérence et validation

JavaScript propriétaire et outils Node utilisent une configuration Prettier
fixée ; les scripts et tests Python utilisent Black. Les données générées,
distributions tierces, archives et contrats visuels restent exclus du formatage.
`package.json` expose les commandes de service, contrôle, tests et formatage.
Le SDK existant reste fixé et le lock npm est cohérent. Les dépendances Python et
de test sont explicites. Les fichiers privés, caches et sorties sont ignorés ;
`.env.example` documente uniquement des valeurs factices pour les outils.

Les nouveaux contrôles couvrent les helpers mutualisés, l'initialisation cloud,
les références publiques et l'équivalence à la base avant refonte. Le test de
parité protège seize écrans ; les parcours existants vérifient les comportements
qui ne se résument pas au DOM. La comparaison indépendante des autres contrôleurs
retrouve 244 fonctions nommées identiques et trois remplacements par les helpers
testés, sans autre modification de fonction.

Validation finale :

- `npm test` : **26/26 suites réussies**, soit neuf suites Node et dix-sept
  suites Chromium, sans exclusion de jeu. Comptes, droits SQL, statistiques,
  Culture G., drapeaux, tous les jeux, défilement, audio et PWA sont couverts.
- Les seize écrans conservent exactement leurs textes, DOM, dimensions et styles.
  Les données, CSS, images existantes, polices et migrations sont inchangés.
- `npm run check` : syntaxe JavaScript et **1 952 références locales** valides,
  manifest, ressources hors ligne et dépendances cohérents.
- Formatage Prettier et Black, syntaxe Python et `git diff --check` valides.
- Les huit commandes Python d'outillage répondent à `--help` sans modifier
  de banque. Aucune dépendance npm préexistante n'a changé de version ou de lock.

Les parcours PWA passent à la racine et sous `/Jeu-du-duc/` : jeux en mode avion,
images, sons, mise à jour des fichiers et du worker, conservation des parties,
suppression des anciens caches et reprise du défilement après une saisie.

Les tests utilisent un vrai navigateur, le SDK Supabase officiel et PostgreSQL
embarqué, avec services distants simulés. Ils ne prouvent pas un déploiement
GitHub Pages, la réception d'un email réel ou les capteurs d'un appareil physique.
La vérification HTTP du site GitHub Pages est refusée par le proxy de cet
environnement (CONNECT 403). Ce refus n'empêche pas l'accès Git au dépôt.
